# 相片打印助手（PhotoPrint）设计规格

日期：2026-11-03　状态：已与用户逐节确认，待用户终审
目标机型：Canon MAXIFY G3800　平台：Windows 桌面

---

## 1. 背景、目标与成功判据

### 1.1 痛点

佳能官方 Windows 软件 Easy-PhotoPrint Editor 的相纸尺寸预设里没有 3R（5寸）选项，用户无法直接打印 5寸照片。

### 1.2 可行性结论（已用官方规格证实）

这不是打印机不支持，而是软件未暴露该尺寸。佳能中国 G3800 规格页写明支持**自定义尺寸：宽 55–215.9mm、长 89–676mm**，而 5寸 = 89×127mm 完整落在该范围内，因此可打印。

### 1.3 目标（第一版）

1. 在应用内可选全部相纸尺寸，含 3R 5寸，以及用户自建任意尺寸。
2. 支持"大纸拼版多张小图"：自动算出 A4 能放几张 5寸并给出张数建议，用户按建议凑够照片一次打完。
3. 每张格子可逐张调整裁切与叠加（裁切模式、文字叠加逐张开关），预览所见即打印所得。（2026-11-07 修订：逐张拖动的裁切偏移已删除，见 gui-exe 设计 §3 控件规则）
4. 依据 G3800 物理边距与"自定义尺寸不支持无边距"的事实，诚实处理白边，不谎报能力。
5. 提供无边距 5寸的唯一物理正确路径：A4 无边距 + 3mm 出血拼版 + 人工裁切。

### 1.4 成功判据

- 真机一键打出 89×127mm 的 5寸照片，实测外形尺寸误差 ≤1mm，且画面未被驱动二次缩放。
- A4 拼 4 张 5寸，裁切线可 guide 出 4 张 89×127mm 成品，误差 ≤1mm。
- 全过程无崩溃；任何驱动拒绝自定义尺寸的情况有明确中文提示与兜底出口。

### 1.5 非目标（明确不做）

- 不做 ICC 色彩管理与色域转换（第一版只保证几何正确，色彩交由驱动）。
- 不做裁切精度自动补偿（人工裁切）。
- 不做照片美颜、证件照换底色、人脸对齐、抠图。
- 不做 macOS / Linux 打印链路。
- 不做无边距的程序化开关（佳能无边距位于驱动私有 DEVMODE 区，无法可靠程序化写入）。

## 2. 事实基线（全部来自佳能中国 G3800 官方规格页）

| 项目 | 数值 |
|---|---|
| 打印宽度 | 最大 203.2mm（8"）；无边距最大 216mm（8.5"） |
| 有边距物理不可印区 | 上 3mm、下 5mm、左 3.4mm、右 3.4mm；LTR/LGL 例外：左 6.4mm、右 6.3mm |
| 推荐打印区额外留白 | 上 31.2mm、下 32.5mm（仅文档类建议，相片打印不采用） |
| 驱动内置纸张 | A4、A5、B5、LTR、LGL、4"x6"、5"x7"、信封(DL/COM10)、正方形(5"x5")、卡片(91x55) |
| 自定义尺寸合法范围 | 宽 55–215.9mm，长 89–676mm |
| 无边距支持纸张 | A4、LTR、4"x6"、5"x7"、8"x10"、正方形 5"x5"、卡片 |
| 不支持无边距的介质 | 信封、高分辨率纸、T恤转印纸、照片贴纸 |
| 自定义尺寸与无边距 | **互斥**——佳能官方支持库明确"Borderless printing on custom paper sizes is not supported" |

**由基线推出的三条硬约束（设计必须服从）**

1. 5寸只能走自定义尺寸 ⇒ 5寸直打**必然留白边**，任何文案不得暗示可消除。
2. 12寸（254×305mm）宽 254 > 215.9 ⇒ **超出本机能力**，必须排除并提示，不能列为预设。
3. 想要无边距 5寸，只能"用支持无边距的大纸打印带出血的 5寸格子，再裁切"。

## 3. 架构总览

### 3.1 分层与依赖方向（单向，禁止反向依赖）

```
app/ (PySide6，唯一有窗口的层)
  ↓ 只依赖
core/ (纯函数：尺寸规格、装箱、裁切、渲染、模式映射)
  ↓ 只依赖
win/ (Windows 打印链路：驱动探测、DEVMODE、GDI、PDF 导出)
```

- `core/` 不得 import 任何 PySide6 或 win32 模块，必须能在无窗口、无打印机环境下运行（CI 与本机验证全靠这条）。
- `win/probe.py` 输出纯 dict，可被 mock，供 `core/` 消费。
- `app/` 不含任何 mm/像素换算逻辑，一律调用 `core/`。

### 3.2 目录结构

```
photoprint/

  core/probe_api.py   接收探测 dict，做规格表与驱动实测的比对
  core/pack.py        pack() 装箱纯函数
  core/crop.py        cell_crop_box() 预览与打印共用的裁切纯函数
  core/render.py      render_page() → PIL.Image（含遮罩、裁切线、校准页）
  core/modes.py       三档打印模式定义与默认映射
  win/probe.py        DeviceCapabilities / GetDeviceCaps 能力探测
  win/devmode.py      DEVMODE 继承与改写
```

### 3.3 依赖清单（直接 import 的包必须显式声明，不依赖传递依赖）

`PySide6`、`Pillow`、`pywin32`、`img2pdf`、`pytest`。写入 `requirements.txt` 并在 README 同步一份。凡是代码里直接 `import` 的包，必须在此清单显式声明，不得依赖某个包顺带带进来的传递依赖——否则上游依赖一变就会在用户机器上炸。

## 4. 尺寸规格表

### 4.1 数据模型

```python
{
  "key": "3R",                     # 稳定标识，存盘与配置引用用
  "label": "3R 5寸",
  "w_mm": 89.0, "h_mm": 127.0,
  "role": "paper",                 # paper=可作纸张 / cell=只能作格子(证件照)
  "origin": "custom",              # preset=驱动内置 / custom=只能自定义 / user=用户自建 / spec=只能当拼版格子（证件照类，不对应任何驱动纸张）
  "borderless": False,             # 依据第 2 节基线推定，运行时以驱动探测覆盖
  "margins_mm": {"top": 3.0, "bottom": 5.0, "left": 3.4, "right": 3.4},
  "margin_source": "spec",         # spec=依官方规格推定 / probed=驱动实测 / calibrated=真机校准
  "driver_paper_code": null        # origin=preset 时存 Windows DMPAPER_* 码
}
```

`margin_source` 是诚实性的载体：文案分档必须依据它，而不是依据"程序想要什么"（见 7.3）。

### 4.2 相纸预设（role=paper）

| key | 名称 | 尺寸 mm | origin | borderless | 依据 |
|---|---|---|---|---|---|
| A4 | A4 | 210×297 | preset | **True** | 驱动内置 + 无边距列表 |
| A5 | A5 | 148×210 | preset | False | 驱动内置，不在无边距列表 |
| B5 | B5 | 176×250 | preset | False | 同上 |
| LTR | Letter | 215.9×279.4 | preset | True | 无边距列表；边距用 LTR 特例值 |
| LGL | Legal | 215.9×355.6 | preset | False | 边距用 LTR/LGL 特例值 |
| **3R** | **3R 5寸** | **89×127** | **custom** | **False** | **本项目的立项理由**；官方无边距列表无此项 |

| 5R | 5R 7寸 | 127×178 | preset | True | 驱动内置 `5"x7"` |
| 6R | 6R 8寸 | 152×203 | custom | False | 驱动列表无 `6x8`；宽 152≤215.9、长 203≤676 ⇒ 可自定义 |
| 7R | 7R 10寸 | 203×254 | preset? | 存疑 | 无边距列表有 `8"x10"` 但纸张列表未列出 ⇒ 运行时枚举决定，探测不到则降 custom |

注：4D/宽幅等相纸因地区命名与尺寸不统一，**不内置预设**，由用户走自定义尺寸录入，避免把未核实数字写进硬断言。

### 4.3 证件照格子预设（role=cell，不能当纸张）

| key | 名称 | 尺寸 mm |
|---|---|---|
| ID1 | 一寸 | 25×32 |
| ID2 | 二寸 | 35×49 |
| IDS2 | 小二寸 | 35×45 |
| IDBIG1 | 大一寸 / 护照 | 33×48 |
| USVISA | 美国签证 | 51×51 |

- 上述数值为行业通行规格，允许用户在 UI 内直接修改数值（签证类各国不同，做错不如可改）。
- 这些格子的 `origin` 取 `spec`：它们从不送进驱动当纸张用，因此既不是 `preset`（驱动内置）也不是 `custom`（驱动自定义尺寸）。
- **UI 结构约束**："纸张"下拉只列 `role=paper`，"格子"下拉只列 `role=cell` + 全部 `role=paper`。从结构上杜绝"选了 1寸 却不存在 1寸 的纸"这类不可能输出——这正是官方软件容易误导之处。

### 4.4 运行时驱动能力探测

不信任上面的表，启动后对选中打印机探测一次，冲突时**以驱动为准并在 UI 标注差异**：

- `DeviceCapabilities(DC_PAPERS / DC_PAPERNAMES / DC_PAPERSIZE)` → 驱动真实纸张清单，用于把 `4R` 匹配到驱动中的 `"4x6"`/`"10x15"`/`"2L"` 等名字（地区驱动命名不同）。
- `GetDeviceCaps(PHYSICALWIDTH/PHYSICALHEIGHT)` → 该尺寸下驱动认定的纸张物理尺寸。
- `GetDeviceCaps(PHYSICALOFFSETX/Y)` + `HORZRES/VERTRES` → 真实可打印矩形（即真实边距）。
- 结果写入内存 `probe_report`，可一键导出 JSON 供反馈问题使用。

探测不可用（无打印机/脱机）时，所有边距值回落 `margin_source=spec`，UI 明示"依官方规格推定，未经真机验证"。

### 4.5 自定义尺寸

- 字段：名称 + 宽 + 高（mm，1 位小数），存 `%APPDATA%\PhotoPrint\papers.json`。
- 提交前校验：宽 ∈ [55, 215.9] 且 长 ∈ [89, 676]，**交换判定**（`max(w,h)` 对长边、`min(w,h)` 对短边，因 89×127 横放时长度恰为下限 89）。
- 自定义尺寸强制 `borderless=False`，不可由用户改（防止用户"希望"它无边距）。
- 提供"从驱动已建表单导入"，避免用户重复输入。

## 5. pack() 装箱算法

### 5.1 签名

```python
plan = pack(sheet, cell, gap_mm=0.0, bleed_mm=0.0, allow_rotate=True, printable=None)
# LayoutPlan(cells=[Cell(x_mm,y_mm,w_mm,h_mm,rotated)], count, sheets,
#            waste_mm2, strategy, cuts=[CutLine(x1,y1,x2,y2)])
```

- **装箱默认区域 = 整张纸**（`printable=None` 时）。5.3 的手算基准全按整张纸算（`floor(210/89)` 而不是 `floor(203.2/89)`），默认值必须与基准同口径：A4 打 4R 在 210mm 宽里放得下两张 102mm（204 ≤ 210），扣掉物理边距只剩 203.2mm，会因 0.8mm 之差从 3 张掉到 2 张。代价是**任何要真送打的排版必须显式传 `printable=printable_rect(sheet, borderless_active=…)`**（无边距生效时它返回整张纸），不传就是把照片切进物理边距。`bleed_trim` 模式本就用整张纸。
- **退化情形例外（必须处理）**：调用方显式传 `printable` 后，当格子尺寸大于可打印矩形（如 3R 纸直打一张 3R，`89 > 82.2`）会算出 0 格。此时调用方必须改为整张纸装一格，画面收回可打印区的工作交由渲染层完成（见 6.2），不得报错也不能让内容被边距无声吃掉。
- 格子有效尺寸 = `(cell.w + 2*bleed_mm + gap_mm) × (cell.h + 2*bleed_mm + gap_mm)`，间隔只计在格子之间、不计外圈，故列数公式为 `n = floor((W + gap) / (cw + gap))`。
- `allow_rotate` 默认 True（相片横竖都能排），但 **`role=cell` 的证件照拼版由调用层显式传 False**：旋转会把格子横放，贴出来的证件照就是躺倒的；允许旋转只会让张数虚高（A4 一寸 gap=2 从 56 涨到 66+）。因此 5.3 的寸照基准是在禁旋转前提下成立的。

### 5.2 三级搜索（取张数最多；规模小，可穷举证明最优）

1. **单朝向均匀网格**：枚举两种朝向，`floor((W+g)/(cw+g)) × floor((H+g)/(ch+g))`。
2. **一刀双带（guillotine）**：候选切位取有限集 `{k*cw, k*ch, k*(cw+g), k*(ch+g)}`（k≥1 且严格落在区域内；切在 0 或全长会退化成单带，与第 1 级等价，故不列），横切或竖切为两条矩形带，各自回退到第 1 级最优，相加。
3. **两刀三带**：对第 2 级的每条带再切一刀，递归深度上限 2，防组合爆炸。

**并列决胜**（张数相同时依次比较）：① 总浪费面积最小 → ② 策略更简单优先（均匀网格 > 一刀双带 > 两刀三带）→ ③ 整体外接矩形更接近正方形 → ④ 居中偏差更小 → ⑤ 朝向更统一（同向更易裁切）。

② 必须排在 ③④ 之前。“外接矩形更接近正方形”单用不准：它只量跨度，量不出居中与间隙是否均匀。反例：A4+3R 的一刀双带解（左带宽恰好 89mm，格子贴左边缘）外接框 194×254，比均匀网格的 178×254 更接近正方形，两者张数与浪费全同，前者却不居中、列间隙不等（一边 0mm、一边 16mm）、切缝也不贯通。把“更简单”放在浪费之后、美观之前，混合带就只在张数或浪费上真能赢时才胜出（正如 A4+4R 的 3 比 2），而不是靠把居中解换成贴边解赢得并列决胜。

**切缝取舍规则**：凡严格落在装箱区域内部的格子边界都画线；与区域边界重合的边界不画（纸边就是基准）。居中留白时两侧都要画——只画一侧会留下带白边的半成品，切不出 89×127 的成品；格子恰好铺满某轴时该轴就只剩中间缝，规则自动退化正确。同一条缝上的线段取紧邻该缝的格子在另一轴上的范围之并集，输出合并后的贯通切缝，而非每格四条边（见 6.4）。出血模式（bleed_trim）下切缝按格子外框（块 = 成品 + 2×bleed）出：沿缝切出的是偏大的块，成品尺寸靠二道精裁，精裁线由渲染层按 `Cell.inner_mm()` 叠加显示，不在 `build_cuts` 输出内——外框缝是两带之间的物理落刀位，切成块再精裁比直接按内框落刀更易对齐。

### 5.3 手算基准（写成硬断言，非近似值）

| 纸张 | 格子 | 参数 | 期望 | 手算依据 |
|---|---|---|---|---|
| A4 210×297 | 3R 89×127 | gap=0 | **4** | 竖：`floor(210/89)=2` × `floor(297/127)=2` = 4，占 178×254；横：`floor(210/127)=1` × `floor(297/89)=3` = 3 ⇒ 取 4 |
| A4 | 4R 102×152 | gap=0 | **3** | 单网格竖=2、横=2；切位 y=152 分两带：上带 210×152 放 2 张竖，下带 210×145 放 1 张横（152×102）⇒ 3。**这是混合带存在的价值，比单网格多 1 张** |
| A4 | 5R 127×178 | gap=0 | **2** | 竖 1×1=1；横 `floor(210/178)=1` × `floor(297/127)=2` = 2；面积证明 3 张不可能：3×(127·178)=67818 > 210·297=62370 |
| A4 | 3R + bleed | bleed=3, gap=0 | **4** | 有效格 95×133 ⇒ `floor(210/95)=2` × `floor(297/133)=2` = 4，占 190×266 ≤ 210×297 ⇒ 出血不损失产能 |
| 4R 102×152 | 3R 89×127 | gap=0 | **1** | 竖 1×1；横 `floor(102/127)=0` ⇒ 一张 6寸 塞不下两张 5寸（89×2=178>152），此路直接排除 |
| A4 | ID1 25×32 | gap=2, allow_rotate=False | **56** | `floor(212/27)=7` × `floor(299/34)=8` = 56（寸照不得旋转，见 5.1） |
| A4 | ID2 35×49 | gap=2, allow_rotate=False | **25** | `floor(212/37)=5` × `floor(299/51)=5` = 25 |
| A4 可打印区 203.2×289 | 3R | gap=0 | **4** | 应用边距后仍 2×2（`floor(203.2/89)=2`, `floor(289/127)=2`），证明边距不影响 A4+3R 产能 |

另需两条不变量断言：`4R on A4 = 4` 不可能（需 204×304，304>297）；任何 `count × cell_area ≤ sheet_area` 必须成立（算法不得违反面积上界）。

### 5.4 页与格数

- 照片数 < 格子数：留空格子，状态栏提示"这张纸还剩 N 格"。
- 照片数 > 格子数：自动分页，状态栏给"共需 N 张纸"。
- 反向用法：用户先定"我要在这张纸打 4 张"，算法在候选格尺寸中给建议（服务用户提出的"按建议张数选照片"）。

## 6. cell_crop_box()：预览与打印共用的裁切纯函数

### 6.1 签名与状态模型

每格只存三个与 DPI 无关的数：

```python
CellTransform = {"zoom": 1.0, "dx_mm": 0.0, "dy_mm": 0.0}

def cell_crop_box(photo_w_px, photo_h_px, target_w_mm, target_h_mm,
                  mode, zoom, dx_mm, dy_mm) -> (l, t, r, b)   # PIL crop box，像素
```

### 6.2 语义（写进代码注释，防止后来人误读）

- `fit_to_printable` / `fill_printable` 的**目标矩形相同**（都是可打印区），二者只在"是否裁掉超出内容"上不同。
- 目标矩形统一按 `格子内框 ∩ 可打印矩形` 计算：正常拼版下格子本就落在可打印区内，交集等于原框；而“整张纸只放一格”（5.1 退化情形）时，正是这个交集把画面收进可打印区，避免边缘内容被物理边距无声裁掉。
- `bleed_trim` 的目标矩形是**整张纸 + 出血外扩**，与前两者的矩形不同。
- 常见误读警告：`fill_printable` **不是**"铺满整张纸"——物理上铺不到边缘。

### 6.3 钳制规则

- `fill` 模式：`zoom ≥ 1.0`（1.0 = 恰好覆盖目标），且 `dx/dy` 钳制使照片边缘不得退进目标矩形内部（不许拖出白边）。
- `fit` 模式：`zoom ≤ 1.0`（整幅完整显示），`dx/dy` 钳制使照片不得移出可打印矩形。
- 缩放锚点：滚轮以鼠标落点为锚换算成 `dx/dy` 增量，保证"指哪扩哪"。

### 6.4 预览与打印的一致性（本项目最高优先级的禁则）

- 预览层与打印层**必须调用同一个 `cell_crop_box`**，预览只是把 `target_*_mm` 换成屏幕像素目标。
- 禁止在 `app/` 内复制或重写任何 crop/缩放换算；禁止出现第二套 mm↔px 公式。
- 唯一换算入口：`mm_to_scene(mm) = round(mm*10)`（场景坐标 1 单位 = 0.1mm）。
- 用测试固化该禁则：同一组 `(photo_size, target, mode, zoom, dx, dy)` 下，断言预览 crop box 与打印 crop box 归一化到同一参考系后逐位相等。理由：预览一套、打印一套是这类工具最致命的 bug——屏幕构图满意、打出来切头，且本机无打印机，只能靠断言拦住。

## 7. 三档打印模式与无边距处理策略

### 7.1 模式定义

| 模式 | 目标矩形 | 画面内容 | 白边结果 | 需裁切 |
|---|---|---|---|---|
| `fit_to_printable` | 纸张 − 物理边距 | 完整显示，缩进 | 有（必然，不可消除） | 否 |
| `fill_printable` | 纸张 − 物理边距 | 铺满，超出裁掉 | 有（必然，不可消除） | 否 |
| `bleed_trim` | 整张纸 + 每格外扩 `bleed_mm` | 铺满出血区 | 裁切后**无白边** | **是** |

### 7.2 默认映射（用户可逐次覆盖，并记住上次选择）

```
格子 role=cell（证件照）      → fit_to_printable     # 丢头即废片，绝不裁
纸张 origin=custom（含 3R）   → fill_printable       # 无法无边距，只能接受白边
纸张 borderless=True 且多格   → bleed_trim (bleed=3) # 唯一无边距路径
纸张 borderless=True 且单格   → fill_printable       # 无边距能力在驱动侧继承即可，不必裁
```

`bleed_trim` 第一版**必须纳入**（已确认）：它不是新子系统，只是 `pack(bleed_mm=)` + 已有裁切线 + 一个模式分支，且 A4+3R 出血后产能仍为 4 张；不做它，本工具对"无边距 5寸"就没有答案，用户仍会退回官方软件打 6寸再裁。撤销成本低（删一个模式分支），核心链路不受影响。

### 7.3 UI 诚实文案口径（按证据分档）

- `margin_source=probed/calibrated`（有实测）：`可打印区 82.2×119.0mm（驱动实测边距 左3.4/上3.0/右3.4/下5.0mm）`
- `margin_source=spec`（仅依规格推定，开发期常态）：`依佳能官方规格，该尺寸边距约为 上3/下5/左右3.4mm，故将保留白边；实际值以真机校准为准`
- **禁用表述**：`borderless=False` 时出现"无边距"；`fill_printable` 时出现"铺满整张纸"；未校准时给出 0.1mm 级白边承诺。
- 驱动实测与官方规格不符时**两个数同时显示并标红差异**，不静默取其一。
- `bleed_trim` 一律显示标签"需人工裁切"，不显示"无边距打印"（结果是无边距，但动作不是打印就能完成的，文案必须描述动作）。

### 7.4 无边距生效时边距归零（易错点，必须先定清）

上述 `fit_to_printable` / `fill_printable` 的目标矩形一律是"纸张 − `margins_mm`"。但当用户在驱动里勾了无边距且驱动探测回报 `PHYSICALOFFSETX/Y = 0` 时，该尺寸的有效 `margins_mm` **必须置为 0**，于是目标矩形自动等于整张纸，`fill_printable` 就真的是铺满全纸（例：4R 6寸 + 驱动无边距 → 102×152 满版，无需裁切）。

规则：`margins_mm = 0` 仅在**探测或校准实测**到无边距生效时成立；`margin_source=spec` 时不得假设它为 0。不定清这条，实现者会以为"4R 也必然留白边"，或反过来在自定义尺寸上偷偷按 0 处理（那就是第 7.3 条禁止的谎报）。

## 8. 交互设计（PySide6 QGraphicsView）

### 8.1 场景与图层

1 场景单位 = 0.1mm，整数建坐标，避免 float 累积误差。图层自下而上：

| 层 | 内容 | 样式 | 默认 |
|---|---|---|---|
| L0 | 纸张白底 + 投影 | 纯白矩形 | 开 |
| L1 | **不可打印遮罩** | 四边半透明斜纹带，宽=`margins_mm`（斜纹只压线不铺底，白纸仍是白的；实心灰只在画面会被裁时叠在内容上） | 开（可淡出） |
| L2 | 格子边界 | 0.1mm 灰虚线 | 开（可关） |
| L3 | 照片 | `PhotoCellItem` | — |
| L4 | **裁切参考线** | 0.35mm 实线、15% 灰、贯通整条切缝 | 开（仅当格子数 ≥ 2） |

L1 是界面诚实性的核心：让用户在打之前就看到"这条边打不出来"。

### 8.2 操作表

| 操作 | 行为 | 约束 |
|---|---|---|
| 资源管理器拖入 | 追加到照片列表，按文件名排序，EXIF Orientation 立即归正 | 支持 jpg/png/webp/tiff；HEIC 提示装 Pillow 插件 |
| 列表拖到某格 | 该格换片 | 拖到纸面外 = 追加到首个空格 |
| 格内按住拖动 | 改 `dx_mm/dy_mm`，跟手 | 按 6.3 钳制 |
| 滚轮 | 以光标为锚 ×1.1 | `fill` [1.0,4.0] / `fit` [0.2,1.0] |
| Ctrl+滚轮 | ×1.02 精调 | 同上 |
| 双击格子 | 重置（居中 + 最小覆盖缩放） | — |
| 方向键 | ±0.5mm | Ctrl+方向键 ±0.1mm |
| 右侧面板按钮 | ←↑↓→ ±0.5mm、放大/缩小、重置、适配整张纸 | 与键盘共用同一实现，禁止重复逻辑 |
| 复制到所有格子 | 当前格 `zoom/dx/dy` 套到本页全部格 | 证件照同尺寸的主要省力点 |
| 右侧面板数值 | 显示并可手输 `zoom / dx_mm / dy_mm / 出血状态` | 实时刷新 |

不做 undo/redo（用"单格重置 + 全部重置"覆盖需求）。

### 8.3 视图与性能

- 视图缩放三档：适应窗口 / 100%（按屏幕 96dpi，标注"约等于实际大小"）/ 自由缩放，附 mm 标尺。

- 拖动时 `setCacheMode(DeviceCoordinateCache)`，仅重绘被拖格子。

## 9. 打印链路（GDI 直打）

### 9.1 DEVMODE：继承私有区，只改纸张字段

佳能的无边距、介质类型、鲜艳模式等设置位于驱动私有 DEVMODE 扩展区。保住它们的唯一办法是**先取驱动当前默认再改字段**：

```python
size = DocumentProperties(hPrinter, None, name, None, None, 0)
buf  = create_string_buffer(size)          # 按 size 分配，不得按 sizeof(DEVMODE)
DocumentProperties(hPrinter, None, name, buf, None, DP_INQUIRE)
dm   = PyDEVMODE(buf, size)                # 保留 cbSize 与私有区，禁止截断

dm.dmFields        |= DM_PAPERSIZE | DM_PAPERLENGTH | DM_PAPERWIDTH | DM_DEFAULTSOURCE | DM_SCALE
dm.dmPaperSize      = DMPAPER_USER(259) 或驱动预设码
dm.dmPaperLength    = int(h_mm * 100)    # 单位 0.1mm
dm.dmPaperWidth     = int(w_mm * 100)
dm.dmDefaultSource  = DMBIN_USER         # G3800 后端托盘
dm.dmScale          = 100                # 关键：禁止驱动缩放，保证 1:1

hdc = CreateDC(name, None, port, buf)
```

以上为**伪代码，表达的是操作顺序与必须保留的语义**，不是 pywin32 的确切调用形态。实现时以 pywin32 实际 API 为准（`DocumentProperties` 的 devmode 取回方式、`PyDEVMODE` 的构造与写回 buffer 的形式需按本机 pywin32 版本确认），但"按驱动回报的 size 分配 buffer、继承私有区、不改 `cbSize`、只改纸张相关字段"这四条语义不可变。

**禁则（写成断言）**：不得 new 空 DEVMODE 再填字段（会丢无边距与介质设置）；不得改 `cbSize`；不得按 `sizeof(DEVMODE)` 截断 buffer；`origin=preset` 的尺寸必须用驱动预设码而非 custom（只有预设码才可能继承无边距标志）。

### 9.2 回读校验

`CreateDC` 后用 `GetDeviceCaps(PHYSICALWIDTH/PHYSICALHEIGHT)` 换算 mm，与请求值比对，**容差 0.5mm**。超限即判定"驱动忽略了自定义尺寸"→ 中止直打、给中文解释、自动指向 PDF 兜底与建表单指引。

### 9.3 DPI 与位图

- 目标 dpi = `min(驱动 LOGPIXELSX, 用户上限)`，默认 300，可选 600。G3800 标称 4800×1200，若按驱动 dpi 直出 A4 将是约 40000×25000 px，必然爆内存。
- 参考量：A4@300dpi ≈ 2480×3508 px；@600dpi ≈ 4960×7016 px（RGB 约 104MB）。
- 送图：PIL 按目标 dpi 渲染，经 `PIL.ImageWin` 以 `StretchBlt` + `HALFTONE` 填满设备可打印矩形，缩放交驱动，内存可控。
- 顺序：probe → 校验 → 构造 DEVMODE → CreateDC → BeginDoc → 逐页 `render_page` → BitBlt/StretchBlt → EndPage → EndDoc → DeleteDC。

### 9.4 色彩

RGB → CMYK 由驱动完成。第一版不做 ICC，UI 固定提示"请关闭驱动的『照片增强/鲜艳』模式，否则偏色并非本工具几何误差"。

## 10. PDF 兜底路径

同一 `render_page` 结果 → `img2pdf` 无损嵌入 → **PDF 页面尺寸精确等于目标纸张 mm**（89×127 或 210×297）。用户在 Acrobat/SumatraPDF 以"实际大小 / 100% 缩放"打印，驱动内选同名或自建表单。

触发条件：驱动忽略自定义尺寸、DEVMODE 解析异常（pywin32 版本差异）、用户主动选择。
附带一次性指引："如何在佳能驱动首选项中建立 3R(89×127) 自定义表单"——建过一次后 Windows 会记住，直打与 PDF 两条路都顺。

## 11. 校准页闭环（本机无打印机条件下的命脉）

入口 `打印校准页`，在 A4 上输出：

1. **四条纸边到第一条墨线的刻度尺**，每 10mm 一格并标数字 → 用户量出真实四边距。
2. **一个 20.00mm 实心方框** → 用户量实际边长；≠20mm 说明驱动在做缩放（`dmScale` 被忽略或"适合页面"开着），UI 给出关闭指引。
3. 四角 L 形对齐标记 + 一条对角线 → 检查偏移与裁切。
4. 角落打印当前配置摘要，含边距来源（`spec`/`probed`/`calibrated`）。

用户在 `calibrate_dialog` 回填 4 个边距 + 方框实测边长 → 写入 `papers.json` 的 `margins_mm` 覆盖，并把该尺寸 `margin_source` 由 `spec` 升级为 `calibrated`，7.3 的文案自动切到实测档。

价值：把"真机误差"变成可量化输入，而不是靠猜；也让用户能用一个数字（量到的偏差）向我反馈问题。

## 15. 已知限制

1. **开发机没有 G3800 打印机**（`Get-Printer` 仅列出 Print to PDF / XPS / OneNote 三个虚拟打印机）。所有几何正确性靠单元测试 + PDF 对照验证；无边距、驱动是否接受 89×127、真实边距数值三项必须真机确认，由第 11 节校准页闭环收敛。第一版交付时这几项标注为"待用户真机验证"，不声称已验证。
2. **人工裁切**：`bleed_trim` 成品需用户用切纸刀/尺子沿裁切线裁，第一版不做裁切精度补偿，也不承诺裁切后误差。
3. **不做 ICC**：色彩由驱动决定，偏色不在本工具责任范围，UI 有固定提示。
4. **无边距不可程序化**：佳能无边距开关在驱动私有 DEVMODE 区，本工具只能"继承用户已勾选的设置"，不能代为打开；因此 6寸无边距需要用户在驱动首选项里勾一次，之后被继承。
5. **驱动差异风险**：部分佳能驱动版本要求先在驱动内建立自定义表单才接受程序化自定义尺寸；已用回读校验 + PDF 兜底 + 建表单指引覆盖，但无法在第一版消除该一次性人工步骤。
6. 机型规格基于佳能中国 G3800 公开规格页，其他机型需按第 4 节重新填表（数据模型已支持）。

- **由用户追加诉求推导**：`bleed_trim`（源于"是否能无边距"与"大纸拼版"两个诉求的交集）。
- **工程判断新增（非用户要求）**：驱动能力探测、0.5mm 回读校验、PDF 兜底、校准页闭环。理由：开发机无打印机，若无这三项，几何精度无从验证。
- **已确认的三个口径**：证件照作格子非纸张；`gap_mm` 默认 0 且裁切线默认开（仅格子数 ≥2）；`bleed_trim` 纳入第一版且校准页保留。

## 17. 实现顺序（第一版内部分批，每批可独立验收）

| 批 | 内容 | 本批完成的可验收证据 |
|---|---|---|
| M1 | `core/` 全部（specs/pack/crop/modes/render）+ `tests/` 硬断言 | 5.3 全部基准通过；`_lab/` 能输出一张 A4+3R 带裁切线的 PNG，可用尺子量出 89×127 格位 |
| M2 | `win/` 全部（probe/devmode/gdi_print/pdf_export） | 用 Microsoft Print to PDF 打印，PDF 页面尺寸 = 89×127mm（误差 0）；探测模块 mock 测试通过 |
| M3 | `app/` 主窗口与预览交互 | offscreen smoke 测试通过；手工走通"拖 4 张→选 A4+3R→拖动微调→打印" |
| M4 | 校准页 + `papers.json` 覆盖回写 + 指引文案 | 校准页可打印；回填实测值后 `margin_source` 变 `calibrated` 且文案切档 |
| M5 | **用户真机验证**（不在我这边） | 用户打出 5寸并量尺寸 → 回填 → 确认误差 ≤1mm |

M1–M2 是我能在本机独立验证到底的部分；M5 是唯一必须由用户完成的验收环节，交付时明确标示"几何已验证、无边距与驱动接受度待真机确认"。
